0.028 OPSD-V is an on-policy self-distillation scheme: a student follows its own exact infere...
Contributions
OPSD-V is an on-policy self-distillation scheme: a student follows its own exact inference-time AR rollout (own KV cache), while a teacher is evaluated at the same visited denoising states but with a cleaner AR-consistent cache where older history is replaced by real long-video context, providing dense denoising-level corrective targets without changing the sampler or inference-time cache mechanism.
Applicable to our work
The on-policy correction pattern (student rolls out exactly as at inference time; a teacher supplies corrective targets at the same visited states using cleaner context) is a directly transferable template for DAgger-style repair distillation on hexgen's own broken program rollouts -- e.g. having a teacher re-derive a corrective continuation from a verifier-clean program state whenever the student's own autoregressive rollout drifts, rather than training only on clean expert trajectories.
Additional context
Demonstrated only on few-step AR video diffusion, not on executable program grammars, so transfer to hexgen's discrete program rollouts is unproven. No released code. The 'cleaner-context teacher' has no direct hexgen analogue — you'd need to synthesize one (e.g. verifier-repaired continuations), which is a moderate new training-loop component rather than a drop-in.

0.024 Study of Best-of-N zero-shot TTS candidate selection using an ASR verifier; shows verif...
Contributions
Study of Best-of-N zero-shot TTS candidate selection using an ASR verifier; shows verifier rankings reverse depending on evaluator ASR family despite near-identical representations, then proposes cross-family rank ensembles (rank-averaging and conjunctive max-rank) that reduce this confound.
Applicable to our work
hexgen also selects among best-of-N candidate programs via a frozen verifier; this paper's core finding -- that apparent verifier quality/oracle-headroom recovery can be an artifact of evaluator identity/lineage rather than true representational quality -- is a direct methodological caution for validating and reporting our own best-of-N + verifier pipeline, and its cross-family rank-ensembling fix is a candidate technique if we ever use multiple imperfect verifiers/proxies.
Additional context
Evaluated only in zero-shot TTS with learned ASR verifiers; hexgen's verifier is a single frozen deterministic checker, not an ensemble of learned models, so the cross-family confound may not bite us directly. The value here is evaluation hygiene for best-of-N reporting rather than a capability gain — cheap to adopt only if we ever add proxy verifiers.

0.017 IrisFlow is a query-based, open-vocabulary flow-matching framework: candidate materials...
Contributions
IrisFlow is a query-based, open-vocabulary flow-matching framework: candidate materials/components enter as wavelength-aware optical tokens (not learned fixed identities) supplied at query time; discrete component/material sequences are generated by discrete flow matching over the query-time candidate bank, and continuous parameters (layer thickness) are generated by continuous flow matching without discretization -- jointly, in one 136M-parameter model.
Applicable to our work
Directly analogous open-vocabulary/joint discrete-continuous generation pattern: hexgen currently uses a small CLOSED coordinate vocabulary and fixed program-command tokens; IrisFlow's query-time candidate bank + discrete-flow-matching-for-choices/continuous-flow-matching-for-parameters recipe is a candidate mechanism for generalizing the coordinate vocabulary and command parameterization to real/out-of-distribution CAD parts without retraining -- squarely addresses the domain-gap and structured/schema-constrained generation care areas.
Additional context
The domain is optical-coating inverse design, not CAD/geometry — the relevance is by analogy (open-vocabulary + joint discrete/continuous flow matching), not a direct method transfer. Implementation cost is high: a flow-matching generator is a substantial departure from the current autoregressive pointer-decoder. No released code noted.

0.012 Hallucination Self-Play (HSP) co-evolves a detector and a generator from the same base...
Contributions
Hallucination Self-Play (HSP) co-evolves a detector and a generator from the same base model: the detector is fine-tuned on human-labeled data then used as a reward model to train the generator via RLAIF to produce increasingly hard-to-detect hallucinations; the evolved generator's synthesized hallucination data is then used to further optimize the detector via rule-based reinforcement learning.
Applicable to our work
The generator/detector co-evolution loop (detector trained on labeled data, then used as a reward signal to train an adversarial generator, whose harder outputs retrain the detector) is a transferable self-play/verifier-in-the-loop training template; hexgen's frozen verifier is deterministic rather than learned, but the same co-evolving flywheel structure could apply if we ever train a learned proxy verifier or a rollout-difficulty generator to stress-test the program decoder.
Additional context
The co-evolution loop assumes a learned detector/reward model; hexgen's verifier is frozen and deterministic, so applicability is speculative and would first require training a learned proxy verifier or a rollout-difficulty generator. Evaluated on RAGTruth (NLP faithfulness), far from geometry/program synthesis.
