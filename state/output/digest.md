  - _Contributions:_ OPSD-V is an on-policy self-distillation scheme: a student follows its own exact inference-time AR rollout (own KV cache), while a teacher is evaluated at the same visited denoising states but with a cleaner AR-consistent cache where older history is replaced by real long-video context, providing dense denoising-level corrective targets without changing the sampler or inference-time cache mechanism.
  - _Applicable to our work:_ The on-policy correction pattern (student rolls out exactly as at inference time; a teacher supplies corrective targets at the same visited states using cleaner context) is a directly transferable template for DAgger-style repair distillation on hexgen's own broken program rollouts -- e.g. having a teacher re-derive a corrective continuation from a verifier-clean program state whenever the student's own autoregressive rollout drifts, rather than training only on clean expert trajectories.
  - _Additional context:_ Demonstrated only on few-step AR video diffusion, not on executable program grammars, so transfer to hexgen's discrete program rollouts is unproven. No released code. - **Hallucination Self-Play (HSP) co-evolves a detector and a generator from the same base...** · score 0.012
  - _Contributions:_ Hallucination Self-Play (HSP) co-evolves a detector and a generator from the same base model: the detector is fine-tuned on human-labeled data then used as a reward model to train the generator via RLAIF to produce increasingly hard-to-detect hallucinations; the evolved generator's synthesized hallucination data is then used to further optimize the detector via rule-based reinforcement learning.
  - _Applicable to our work:_ The generator/detector co-evolution loop (detector trained on labeled data, then used as a reward signal to train an adversarial generator, whose harder outputs retrain the detector) is a transferable self-play/verifier-in-the-loop training template; hexgen's frozen verifier is deterministic rather than learned, but the same co-evolving flywheel structure could apply if we ever train a learned proxy verifier or a rollout-difficulty generator to stress-test the program decoder.
  - _Additional context:_ The co-evolution loop assumes a learned detector/reward model; hexgen's verifier is frozen and deterministic, so applicability is speculative and would first require training a learned proxy verifier or a rollout-difficulty generator. Evaluated on RAGTruth (NLP faithfulness), far from geometry/program synthesis.
